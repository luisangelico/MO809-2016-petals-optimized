Measurement protocol

Common to every experiment — each measured request follows the same flow:

  1. Objective declaration — the client sets α, a latency budget or a quality floor; the objective travels per request in a ContextVar, so concurrent requests can carry different objectives.
  2. Route discovery — the router reads the DHT, picks spans and builds the chain; that decision's time is recorded in ms (the router's overhead).
  3. Generation — 20 tokens with greedy (deterministic) decoding; the client timestamps the first token (TTFT) and measures tok/s after it.
  4. Evaluation — the generated text is compared against the local fp32 reference: NLL per token, token agreement; where applicable, last-word exact match (LAMBADA).
  5. Logging — one CSV row per request: TTFT, tok/s, decision time, route (spans@peers), activation bytes, NLL, accuracy. Failed requests are filtered out of the means and counted separately.

Setup of each measurement campaign

  • DHT bootstrap — t490-founder brings up the Kademlia node (port 31337); each server connects to it and announces to the DHT the blocks it hosts (model, precision, throughput, state) — the waggle the router reads.
  • Warm-up — warm-up requests before measuring: they let announcements spread and peers get to know each other. Without warm-up, the first routes come out incomplete — that's what contaminated the campaign's early runs (α=1 appeared faster than α=0 before the topology stabilized).
  • Execution — the client (on the Mac) runs the Nectar router with one objective per run (router/run_client.py --objective …); each run produces one full CSV, and the 5-step protocol above applies to every request in it.
  • Network conditions — Mac↔T490 on the same LAN; the T14 sits on the corporate network, the slowest link in the topology — that asymmetry between replicas is what gives the router something to choose.

The means come from 5 repetitions per α level with the same prompts; the final campaign repeated the full protocol 11 times (sweep-*.csv) to cover the link's natural variation. The error bars in the figures are the per-request standard deviation across prompts — prompt variance, not uncertainty about the mean. Failed requests never enter the means; experiment 5 finished with 0 errors across its 150 requests.
