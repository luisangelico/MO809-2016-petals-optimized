Request-aware route optimization for distributed LLM inference

We extend Petals' client-side routing to decide per request which nodes and replicas to use — latency or quality, according to a declared objective — keeping the upstream code untouched, and evaluate per-request route selection across latency and a quality proxy on a heterogeneous 3-host swarm.

A coherent little universe: Nectar (the router) reads the waggle (the DHT telemetry) to pick, per request, the nearest bloom (latency) or the richest nectar (quality).
